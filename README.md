# <p align="center"><img src="icons/fkiosk.svg" /><br />fKiosk — киоск из старого планшета/телефона</p>

Полноэкранный браузер (WebView) для Android 4.2+, без root.

## Возможности
- Автозапуск при загрузке системы с настраиваемой задержкой запуска.
- Если страница недоступна — N попыток с паузой P секунд (N = 0 — без ограничений).
- Автообновление страницы по расписанию: crontab из 5 полей (`59 * * * *` по умолчанию — раз в час). Пустое поле — автообновление выключено.
- Обновление свайпом вниз: когда страница прокручена к самому верху, потяните вниз до появления пиктограммы «обновить» и отпустите.
- Запуск другого приложения свайпом вверх в нижней половине экрана (появляется пиктограмма «домой»). Приложение выбирается в настройке «Запускать приложение»; подходит и штатный лаунчер. Если приложение не выбрано, жест не работает. Срабатывает, когда страница прокручена до конца или не прокручивается.
- Автостарт приложений и команд shell после загрузки системы: настраиваемый список (порядок, пауза перед каждым пунктом, включение/отключение пунктов), см. раздел ниже.
- Экран не гаснет и не затемняется, показывается поверх экрана блокировки.
- Опционально: игнорирование ошибок SSL-сертификата (самоподписанные сертификаты, старые устройства).
- Для слабых устройств: переключатель аппаратного ускорения, периодическая очистка памяти и журнал состояния (см. раздел «Зависания и диагностика»).

## Автостарт приложений и команд
После загрузки системы (при первом старте киоска) выполняются включённые пункты списка сверху вниз. Список настраивается в **Настройки → Автостарт приложений и команд**: кнопка «Добавить», нажатие на пункт — изменить или удалить, кнопки ↑ и ↓ меняют порядок, галочка слева временно отключает пункт.

Параметры пункта:
- тип: **приложение** (выбирается из установленных, подходит и штатный лаунчер) или **команда shell**;
- **пауза перед запуском**, сек;
- для команды shell — опция **«Использовать root»** (команда выполняется через `su -c`; без root недоступна);
- для команды shell — опция **«Ждать завершения команды»**: следующий пункт запускается только после завершения этой команды (не дольше 5 минут). Без неё команда запускается в фоне, и киоск сразу идёт дальше.

Команда без root выполняется от имени самого приложения, поэтому подходят только действия, доступные обычному приложению, например `am start -n пакет/.Активность`. Если пункт не удалось запустить (приложение удалено, нет `su`), он пропускается; общий результат последнего запуска («запущено N из M») показан под пунктом настроек.

Внутри каждого пункта есть кнопка **«Тест»**: она выполняет пункт сразу с текущими значениями полей (даже несохранёнными); команда при тесте выполняется с ожиданием, кнопка превращается в «Стоп». Там же показано, когда пункт запускался в последний раз и с каким результатом (для команды — код возврата), а для команды shell ещё и **журнал выполнения** (вывод команды, не более 16 000 знаков). Журнал можно прокручивать, выделять текст долгим нажатием или скопировать целиком кнопкой «Копировать журнал». Результат и журнал сохраняются и для запусков при загрузке системы; у команды без ожидания они обновятся, когда она завершится.

После запуска последнего пункта киоск ждёт «Задержку запуска» и возвращается на экран. На Android 10 и новее для возврата и запуска очередных приложений нужно разрешение «Поверх других окон».

Если раньше был настроен прежний список приложений (с общей паузой), при первом открытии он автоматически переносится в новый формат.

## Зависания и диагностика
Если устройство (особенно слабое, на Android 4.x) со временем зависает или показывает чёрный экран, в настройках в разделе «Стабильность и диагностика» есть три инструмента:
- **Аппаратное ускорение.** Выключение переводит окно киоска на программную отрисовку. Для простой страницы разницы почти нет, а на слабых видеочипах это нередко убирает зависания и чёрный экран. Настройка применяется сразу после выхода из настроек.
- **Очистка памяти, часов.** Старый WebView накапливает память. Раз в N часов киоск сбрасывает кэш, пересоздаёт окно браузера и заново загружает страницу. Выполняется, когда киоск на переднем плане. 0 — выключено.
- **Журнал состояния, минут.** Раз в N минут в файл `Download/fksk.log` дописывается одна строка CSV: время, сколько работает устройство, свободная и общая память, память приложения, заряд, напряжение и температура батареи, от чего идёт питание, сеть и уровень Wi-Fi, состояние страницы, число очисток и режим ускорения, событие (`app_start`, `boot_start`, `cleanup_N`, `log_enabled`). Первая строка файла — заголовок с названиями столбцов; все значения только латиницей и цифрами, пустое значение означает «нет данных» (например, нет батареи). Файл и заголовок создаются сразу, как только вы задали число минут больше нуля, дальше строки дописываются (если файл уже есть, он продолжается). Каждая запись сразу сбрасывается на флеш-память, поэтому последние строки переживают внезапное зависание и перезагрузку по питанию. При размере больше 1 МБ старые строки отбрасываются. 0 — журнал не ведётся и во флеш-память ничего не пишется.

Файл удобно смотреть из любых приложений и скачивать из папки «Загрузки» (Download). На Android 6-9 приложение запросит разрешение на запись; если его не дать, а также если папка недоступна, файл пишется в папку приложения (путь показан в настройках). На Android 10 и новее файл создаётся через MediaStore и виден только той установке, которая его создала: если приложение переустановить, новый файл будет создан под именем вида `fksk (1).log`. Внутри приложения журнал открывается кнопкой **«Открыть журнал состояния»**: его можно прокручивать, выделять и копировать целиком. Пример (заголовок и две строки):

```
time,uptime_s,ram_free_mb,ram_total_mb,low_mem,app_pss_mb,java_heap_mb,native_heap_mb,bat_pct,bat_mv,bat_temp_c,plugged,bat_status,net,wifi_rssi_dbm,page_ok,attempts,cleanups,hw_accel,event
2026-10-27 14:05:12,274353,123,494,0,85,12,40,100,4150,31.0,ac,full,WIFI,-55,1,0,0,1,app_start
2026-10-27 14:10:12,274653,121,494,0,86,12,41,100,4150,31.2,ac,full,WIFI,-54,1,0,0,1,
```

После зависания посмотрите последние строки перед разрывом по времени: нулевая или очень малая свободная память и `low_mem=1` указывают на нехватку ОЗУ, просевшее `bat_mv` или смена `plugged` на `none` — на блок питания и кабель, высокая `bat_temp_c` — на перегрев, `net=none` — на потерю сети.

## Как попасть в настройки
- долго нажать (удерживать палец) на экране, или
- кнопка «Меню» (если есть), или
- настройки откроются сами при первом запуске, пока не задан адрес.

## Установка и настройка устройства
Начиная с версии 1.3.0 имя пакета приложения — `com.ffps.fksk` (раньше `com.ffps.ksk`). Старую версию нужно удалить с устройства, настройки при этом сбрасываются.

1. Скопировать `fKsk-*.apk` на устройство и установить (разрешить установку из неизвестных источников).
2. **Один раз запустить приложение вручную** — иначе Android не доставит ему сигнал о загрузке системы.
3. Задать адрес страницы в настройках.
4. В настройках Android: блокировка экрана — «Нет»; по желанию в «Для разработчиков» включить «Не выключать экран» при зарядке.
5. Автозапуск при загрузке:
   - на Android 10 и новее включить разрешение «Поверх других окон» (пункт в настройках приложения), иначе система блокирует запуск из фона;
   - если не срабатывает (на некоторых планшетах прошивка не рассылает сигнал загрузки приложениям) — нажать кнопку Home и выбрать «Киоск» как приложение по умолчанию. Тогда система сама запускает его при загрузке, кнопка Home возвращает в киоск, а запуск штатного лаунчера можно настроить на свайп вверх в настройках киоска.

## Сборка и релизы
Каждый push запускает GitHub Actions. Готовый APK: вкладка **Actions** → запуск → **Artifacts** → `ksk-apk`.

Релиз с APK создаётся при отправке тега вида `vX.Y.Z`. Версия приложения (`versionName`) и её числовой код (`versionCode` = X·10000 + Y·100 + Z, например 10300 для 1.3.0) берутся из тега автоматически, править `app/build.gradle` не нужно (минор и патч — меньше 100). Сборки без тега получают служебную версию `0.0.0-dev`:

```
git add -A
git commit -m "Описание изменений"
git tag v1.3.0
git push origin main v1.3.0
```

Файл `fKsk-1.3.0.apk` (имя тега без буквы `v`) появится на странице **Releases**.

### Постоянная подпись APK
Чтобы новые версии устанавливались поверх старых без удаления (и настройки сохранялись), APK должен подписываться одним и тем же ключом. Для этого в репозитории (**Settings → Secrets and variables → Actions → New repository secret**) задаются четыре секрета:

| Секрет | Что содержит |
|---|---|
| `KEYSTORE_BASE64` | файл хранилища ключей (keystore) в кодировке base64 |
| `KEYSTORE_PASSWORD` | пароль хранилища |
| `KEY_ALIAS` | псевдоним ключа |
| `KEY_PASSWORD` | пароль ключа |

Создать хранилище (один раз; можно использовать то же, что и в других проектах):

```
keytool -genkeypair -v -keystore release.keystore -alias ksk -keyalg RSA -keysize 2048 -validity 10000
```

Получить значение для `KEYSTORE_BASE64`:

```
base64 -w0 release.keystore          # Linux
base64 -i release.keystore           # macOS
[Convert]::ToBase64String([IO.File]::ReadAllBytes("release.keystore"))   # Windows PowerShell
```

Если секреты заданы, Actions собирает release-версию, подписанную вашим ключом, и в логе сборки выводит отпечаток сертификата (SHA-256) для проверки. Если секретов нет (например, в форке), собирается debug-версия с временным отладочным ключом, который создаётся заново при каждой сборке: такую версию нельзя установить поверх старой.

Храните файл `release.keystore` и пароли в надёжном месте и не добавляйте их в репозиторий (`*.keystore` и `*.jks` внесены в `.gitignore`). Потеряв ключ, вы не сможете выпускать обновления, устанавливаемые поверх уже установленной версии.

При первом переходе на постоянную подпись установленную ранее версию придётся один раз удалить, потому что она подписана другим (отладочным) ключом.
