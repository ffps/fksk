# fKiosk — киоск из старого планшета/телефона

Полноэкранный браузер (WebView) для Android 4.2+, без root.

## Возможности
- Автозапуск при загрузке системы с настраиваемой задержкой запуска.
- Если страница недоступна — N попыток с паузой P секунд (N = 0 — без ограничений).
- Автообновление страницы по расписанию: crontab из 5 полей (`59 * * * *` по умолчанию — раз в час). Пустое поле — автообновление выключено.
- Обновление свайпом вниз: когда страница прокручена к самому верху, потяните вниз до появления пиктограммы «обновить» и отпустите.
- Запуск другого приложения свайпом вверх в нижней половине экрана (появляется пиктограмма «домой»). Приложение выбирается в настройке «Запускать приложение»; подходит и штатный лаунчер. Если приложение не выбрано, жест не работает. Срабатывает, когда страница прокручена до конца или не прокручивается.
- Автозапуск других приложений при загрузке системы.
- Экран не гаснет и не затемняется, показывается поверх экрана блокировки.
- Опционально: игнорирование ошибок SSL-сертификата (самоподписанные сертификаты, старые устройства).

## Настройки

| Параметр | По умолчанию | Описание |
|---|---|---|
| Адрес страницы | не задан | При вводе сразу подставляется `http://`. Если схема не указана, добавляется `http://` |
| Число попыток при недоступности | 0 | 0 — без ограничений |
| Пауза между попытками, сек | 10 | |
| Автоперезагрузка страницы | `59 * * * *` | crontab из 5 полей или число минут; пусто — выключено |
| Запускать при загрузке системы | включено | Под галочкой показывается, приходил ли сигнал загрузки |
| Задержка запуска, сек | 10 | Пауза после загрузки перед открытием приложения; 0 — сразу |
| Разрешение «Поверх других окон» | — | Нужно на Android 10 и новее для автозапуска при загрузке |
| Обновление свайпом вниз | включено | |
| Запускать приложение | не задано | Приложение для жеста «свайп вверх» |
| Игнорировать ошибки SSL-сертификата | выключено | |

## Как попасть в настройки
- долго нажать (удерживать палец) на экране, или
- кнопка «Меню» (если есть), или
- настройки откроются сами при первом запуске, пока не задан адрес.

## Установка и настройка устройства
1. Скопировать `fKiosk-*.apk` на устройство и установить (разрешить установку из неизвестных источников).
2. **Один раз запустить приложение вручную** — иначе Android не доставит ему сигнал о загрузке системы.
3. Задать адрес страницы в настройках.
4. В настройках Android: блокировка экрана — «Нет»; по желанию в «Для разработчиков» включить «Не выключать экран» при зарядке.
5. Автозапуск при загрузке:
   - на Android 10 и новее включить разрешение «Поверх других окон» (пункт в настройках приложения), иначе система блокирует запуск из фона;
   - если не срабатывает (на некоторых планшетах прошивка не рассылает сигнал загрузки приложениям) — нажать кнопку Home и выбрать «Киоск» как приложение по умолчанию. Тогда система сама запускает его при загрузке, кнопка Home возвращает в киоск, а запуск штатного лаунчера можно настроить на свайп вниз в настройках киоска.

## Сборка и релизы
Каждый push запускает GitHub Actions. Готовый APK: вкладка **Actions** → запуск → **Artifacts** → `ksk-apk`.

Релиз с APK создаётся при отправке тега вида `v*`. Номер версии задаётся в `app/build.gradle` (`versionName`, `versionCode`):

```
git add -A
git commit -m "Описание изменений"
git tag v1.7
git push origin main v1.7
```

Файл `fKiosk-1.7.apk` (имя тега без буквы `v`) появится на странице **Releases**.

### Постоянная подпись APK
Чтобы новые версии устанавливались поверх старых без удаления (и настройки сохранялись), APK должен подписываться одним и тем же ключом. Для этого в репозитории (**Settings → Secrets and variables → Actions → New repository secret**) задаются четыре секрета:

| Секрет | Что содержит |
|---|---|
| `KEYSTORE_BASE64` | файл хранилища ключей (keystore) в кодировке base64 |
| `KEYSTORE_PASSWORD` | пароль хранилища |
| `KEY_ALIAS` | псевдоним ключа |
| `KEY_PASSWORD` | пароль ключа |

Создать хранилище (один раз; можно использовать то же, что и в других проектах):

```
keytool -genkeypair -v -keystore release.keystore -alias ksk -keyalg RSA -keysize 2048 -validity 10000
```

Получить значение для `KEYSTORE_BASE64`:

```
base64 -w0 release.keystore          # Linux
base64 -i release.keystore           # macOS
[Convert]::ToBase64String([IO.File]::ReadAllBytes("release.keystore"))   # Windows PowerShell
```

Если секреты заданы, Actions собирает release-версию, подписанную вашим ключом, и в логе сборки выводит отпечаток сертификата (SHA-256) для проверки. Если секретов нет (например, в форке), собирается debug-версия с временным отладочным ключом, который создаётся заново при каждой сборке: такую версию нельзя установить поверх старой.

Храните файл `release.keystore` и пароли в надёжном месте и не добавляйте их в репозиторий (`*.keystore` и `*.jks` внесены в `.gitignore`). Потеряв ключ, вы не сможете выпускать обновления, устанавливаемые поверх уже установленной версии.

При первом переходе на постоянную подпись установленную ранее версию придётся один раз удалить, потому что она подписана другим (отладочным) ключом.
